how to read these numbers:
  added per frame is the paired difference in the complete production normalLoop(), including live physics and draw calls
  added cost uses each case's paired idle frame, not subtraction of the baseline totals listed above
  entity additions compare against the same quiet map; negative mass off and standing wave compare against the base field emitter
  negative mass on, torch, diamagnetism, and plasma ball compare against that same field with its active effect off
  code alone times powerUps.do(), block drawing, m.hold(), b.bulletDo(), mobs.loop(), or map drawing, as appropriate
  those code-alone values are the entire named function, including any idle/native work; they are not added costs
  projectile/bot code alone excludes projectile drawing and physics; mob code includes graphics drawn inside its AI function
  therefore code alone can be much smaller than added cost, or exceed it when the baseline already does similar work
  bots/drones/spores have no combat targets; these rows do not estimate their cost while attacking a crowd
  final boss is spawned into each quiet map at its normal radius 300, at 98.9% health for the damaged row
  damaged boss has cleared its opening add-wave and uses motionLaser as its first attack; its fractal health graphic is active
  boss modes are normally randomized; later phases, other attacks, and spawned mobs have different costs

measurement details and limits:
  rounded medians of six paired round averages; each round times 256 frames per state after warm-up, alternating state order
  code alone uses a separate instrumented pass of 128 frames per state per round; timers are outside scene resets
  geometry, energy, projectile counts, and foam size are restored before each frame so cases do not expire or drift
  rendering runs in short bursts with browser yields between them; normal gameplay files and the testing loadout are unchanged
  "noise" means the cost is too small to distinguish reliably from normal timing fluctuations; it does not mean zero cost
  "noisy" means the reported estimate varied substantially between runs; use it for rough scale, not precise comparisons
  these are CPU execution/Canvas submission timings, not complete GPU/presentation times or measured fps
  asynchronous graphics work can add costs that these timings miss, particularly fields using compositing
  this harness differs from the earlier three-row chart; compare rows within this block, not absolute numbers across the two
  on ruins, line of sight uses about 31% of a 60 fps frame budget in measured added CPU time; damaged boss about 4.6%, foam about 3%
  costs depend on hardware, camera position, collisions, targets, and tech combinations; rows are reference cases and do not simply add together

additional projectile, block, mirror, and exit setup notes:
  the new projectile rows complete coverage of the remaining base gun projectiles; laser was already measured in the earlier three-row chart
  projectile rows time existing projectiles, not the cost of spawning a shot, explosions, impact effects, or a gun's sustained firing rate
  shotgun pellets and ice IX geometry are restored before each timed frame so shrinking does not change the case
  wave count/radius are restored; the 10 arcs represent overlapping waves already in progress, not 10 waves fired every frame
